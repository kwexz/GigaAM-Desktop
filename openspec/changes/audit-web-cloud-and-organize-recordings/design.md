## Context

См. proposal.md. Ветка feature/gigaam-desktop-web-autonomy содержит пользовательские незакоммиченные изменения: их нельзя перезаписывать. STATUS объявляет roadmap complete, но 09/10 pending; ROADMAP_RESULT описывает NO-GO и external OAuth blocked. src/lib/cloud-auth.ts реализует только MockOAuthProvider с mock:// URL: это не безопасная реальная PKCE-реализация. sync.ts хранит журнал в Map. Найденные tests/web/recorder.spec.ts работают с capture-harness.html, не основным UI. Доступ к state/EVIDENCE.md через read не удался (binary detection); его содержимое пока не проверено.

В +page.svelte есть runtime detection, но также Desktop IPC imports и локальный тип Item без папок; готовность Web требует проверки маршрута /. browser-storage.ts использует IndexedDB v1 и OPFS. Native live.rs поддерживает FLAC/WAV/MP3, default FLAC; импорт .ogg уже разрешён UI, что не означает поддержку записи Ogg.

## Goals / Non-Goals

Одна Svelte UI, автономный Desktop, долговечный Web local-first, доказательная готовность и совместимые расширения хранения. Не менять имя, ID записей, существующие архивы или порядок очереди ASR; не вводить Node/Python сервис и не обещать браузерное системное аудио повсеместно. Этот change планирует устранение пробелов, но не объявляет завершёнными непроверенные предыдущие этапы.

## Decisions

1. **Аудит как первый gate.** Составить матрицу всех заявлений START_HERE/STATUS с commit/checkpoint/evidence и повторными целевыми проверками. Не читать все исторические tasks подряд; обращаться к доказательствам адресно. Проверить кодировку EVIDENCE read-only и извлечь ссылки безопасным декодированием, не переписывать файл вслепую. Альтернатива довериться passed отвергнута из-за противоречий.
2. **Runtime ports вместо второго UI.** Отделить Desktop IPC от браузерных операций через существующие contracts/ports/WebSession. Основной маршрут / обязан работать без Tauri. Тестировать реальные OPFS/IndexedDB на localhost в поддерживаемом браузере, сетевой ASR отдельно от захвата. Harness оставить как низкоуровневую проверку, не как продуктовый E2E.
3. **Облако — отдельные production adapters.** Реализовать независимые Google Drive и Яндекс.Диск API adapters и UI подключения, долговечные outbox/cursors и восстановление. Перед кодированием зафиксировать актуальные официальные endpoint/scopes, redirect и поддерживаемый grant каждого провайдера; не переносить mock PKCE в production и не предполагать одинаковую поддержку PKCE. Использовать поддерживаемую авторизацию public client без встроенного client secret; если платформа требует доверенного обмена, изолировать его в существующем Rust API с отдельной конфигурацией, не делая облако обязательным для Desktop. Проверять state/redirect, срок и повтор callback, минимальные scopes. Desktop secrets хранить через системный защищённый механизм, browser access tokens по возможности в памяти; не хранить refresh tokens в localStorage. Неподдерживаемую безопасную комбинацию platform/provider явно блокировать, а не обходить безопасность. Согласие и регистрация OAuth остаются external gate.
4. **Организация — логические метаданные.** Добавить folders(id,parent_id,name,position) и folder_id/position для записей, через версионированные SQLite/IndexedDB миграции. Root представлен null, существующие записи получают стабильный начальный порядок. Целочисленные позиции перенумеровывать атомарно среди затронутых соседей; проверять циклы транзакционно. Папки не физические пути аудио. Rename/move/delete-folder отражать в журнале синхронизации; delete переносит содержимое в родителя. DnD и меню «Переместить/Выше/Ниже» используют одни операции. Альтернатива двигать файлы на диске отвергнута ради стабильных ID и восстановления.
5. **Ogg/Opus, не только расширение.** Расширить native ArchiveFormat и существующий bounded cancellable pipeline потоковым Ogg/Opus encoder, с partial-файлом и атомарным завершением. Выбор конкретного Rust crate закрепить после проверки Windows/macOS build и лицензии, без обязательного внешнего ffmpeg. Не менять поток PCM для ASR. Web выбирает MediaRecorder MIME через isTypeSupported и проверку фактического результата: Ogg/Opus либо WebM/Opus; fallback честно подписан. Настройка «Компактный» выбирает по измеренным размерам одинакового речевого материала при принятом качестве (начальная кандидатура mono Opus 24 kbit/s, затем сравнение с доступными профилями). Утверждать абсолютный минимум по размеру без quality constraint бессмысленно; сравнивать только профили, прошедшие decode/duration/разборчивость и отсутствие измеренной регрессии ASR. Явные пользовательские настройки сохраняются.

## Risks / Trade-offs

- [OAuth consent/redirect/CORS зависят от провайдера] → проверять официальные требования и реальные аккаунты отдельно; не называть моки реальной интеграцией.
- [Opus lossy и native dependencies] → сравнение размера/качества/нагрузки, проверка locked сборок, сохранение lossless выбора и recovery spool.
- [Concurrent moves/conflicts] → версии, идемпотентные операции, детерминированное разрешение организации, сохранение конфликтующих текстовых изменений без silent overwrite.
- [Изменения миграций затронут пользовательскую историю] → копии фикстур старой БД, транзакции, backup до upgrade, отсутствие физического перемещения аудио.

## Migration Plan

Сначала зафиксировать аудит текущей рабочей копии и её diff без присвоения пользовательских изменений. Затем отдельными атомарными коммитами Web, cloud, hierarchy, codec; после каждого — профильные тесты. SQLite/IndexedDB повышать аддитивно, переносить существующие записи в root и сохранять порядок. Отказ миграции не должен частично менять данные. Для rollback использовать backup и совместимую версию приложения, не удалять поля/архивы. Итоговый checkpoint создавать только после acceptance и отдельного implementation commit; metadata фиксировать отдельно. Старые маркеры без повторной валидации не переименовывать и не удалять.
