## Why

Отметка о завершении дорожной карты не соответствует собственным pending-статусам и наличию только mock-провайдеров Google/Яндекс. Пользователю нужны проверенная веб-версия, реальные облачные подключения, организация записей и компактный архив без потери существующих данных.

## What Changes

- Перепроверить утверждения START_HERE.md, STATUS.md и финального отчёта по коду и воспроизводимым проверкам; устранить подтверждённые пробелы веб-интерфейса и явно отделить внешние блокеры.
- Подключить Google Drive и Яндекс.Диск к пользовательскому интерфейсу через реальные провайдеры авторизации и синхронизации; моки оставить только для тестов.
- Добавить вложенные папки, перенос записей и папок, ручной порядок, сохранение организации на Desktop и Web.
- Добавить Ogg/Opus для новых архивов и компактный профиль по умолчанию; выбирать реально поддерживаемый контейнер и не перекодировать старые архивы автоматически.
- Зафиксировать проверяемую матрицу готовности без подмены настоящего OAuth mock-тестами.

## Capabilities

### New Capabilities
- `delivery-verification`: воспроизводимая оценка готовности дорожной карты и пользовательских сценариев Web/Desktop.
- `cloud-connections`: реальные подключения Google Drive / Яндекс.Диск и надёжная логическая синхронизация.
- `recording-organization`: долговечная иерархия папок и ручной порядок записей.
- `compact-recording`: Ogg/Opus и компактный профиль записи с честным fallback.

### Modified Capabilities
Нет: существующие основные OpenSpec-спецификации отсутствуют.

## Impact

Затрагиваются Svelte UI, browser capture/storage/session, runtime ports, SQLite storage и Tauri-команды, native archive encoder, OAuth/provider adapters, unit/integration/Playwright проверки и state evidence. Возможны дополнительные обоснованные Rust-зависимости кодирования; новый обязательный серверный стек не вводится. Настройка OAuth-приложений и согласие пользователя — внешние действия. Автозагрузка моделей, переписывание старых архивов и production deployment вне scope.
