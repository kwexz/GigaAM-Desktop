# Диаризация: эксперименты и решение

## Зачем

Искали компактный способ разделить голоса в готовой записи локально, без обязательного облака и автоматической загрузки моделей. Это экспериментальная функция: метки требуют проверки человеком.

## Как проверяли

Использовали существующий ONNX Runtime и [WeSpeaker ResNet34](https://huggingface.co/Wespeaker/wespeaker-voxceleb-resnet34): модель размером 26 534 127 байт загружается пользователем отдельно и проверяется по SHA-256. Для фрагментов транскрипта извлекаются голосовые векторы и группируются на двух говорящих; короткие фрагменты могут остаться без метки.

Проверяли настоящий inference модели, один одноголосый фрагмент, синтетическую запись с размеченными голосами и одну длинную пользовательскую запись. Исходное аудио и текст при анализе не изменяются; метки записываются после успешного завершения.

## Результаты

- **Положительные:** модель выдала корректные по формату векторы; на синтетическом примере 8 из 8 неперекрывающихся реплик двух говорящих совпали с разметкой. Одноголосый контрольный пример был отклонён как неоднозначный.
- **Отрицательные:** первоначальная принудительная кластеризация ошибочно делила одного человека на двух. После введения порога уверенности запись длительностью около 29 минут с 315 сегментами отклонялась, хотя в ней есть два голоса.
- **Настройка:** снижение минимального запаса уверенности с 0,20 до 0,13 позволило обработать длинную запись, сохранив результаты указанных контрольных примеров. Правильность её меток не измерена: эталонной разметки нет.
- **Ограничения:** только две группы; пересекающаяся речь, реальные встречи с разметкой, DER, разные микрофоны и качество на разных языках не проверены. Алгоритм может ошибаться или отказаться от разметки. `Speaker 1/2` не означает автоматически «я/собеседник».

## Решение

Оставить WeSpeaker и локальную обработку как экспериментальный режим для готовых записей. Модель загружается только по запросу; результат необходимо проверять и при необходимости переименовывать говорящих. Для устойчивого улучшения нужны размеченные записи с разными условиями и отдельная оценка пересечений речи.

Сравнение с подходом [GigaAMGUI](https://github.com/dubr1k/GigaAMGUI/blob/main/src/core/diarization/onnx_backend.py) показало, что там дополнительно используется модель сегментации речи и пересечений; в текущей реализации GigaAM Desktop она не подключена. Соседний эксперимент по аудиокодекам описан в [OGG_MEASUREMENTS.md](OGG_MEASUREMENTS.md).
