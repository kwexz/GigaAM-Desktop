# Проверка `untildone` на Windows и сравнение с локальным плагином

Дата: 2026-10-28. Хост: Windows, OpenCode v2.2.0, Node v24.11.1, `opencode` в PATH.
Проверялся `github.com/yuya-takeyama/untildone` (clone `--depth 1`) в
`C:/Users/User/AppData/Local/Temp/opencode/untildone-eval`. Рабочий проект GigaAM,
глобальный task-continuity plugin и настройки OpenCode не изменялись.

## Вердикт

**Не подходит как замена локальному плагину на этой машине.** Причина не в качестве
идеи, а в исполнении: на Windows `untildone` не может запустить исполнителя вообще.
Плюс он требует ключ Deep Infra и не опубликован в npm.

При этом его модель прогресса (счётчик tool-событий, git-сигналы, судья, лимиты,
`resume`) содержательнее нашей. На Linux/macOS с ключом Deep Infra он, вероятно,
работоспособнее нашего плагина — это **не проверено**, запуск с моделью не выполнялся.

## Что проверено фактически

| Проверка | Команда | Результат |
|---|---|---|
| Публикация в npm | `npm install untildone` | **E404** — пакета нет, хотя README предлагает `npm i -g untildone` |
| Собственные тесты | `npm test` в репозитории | **46 pass / 6 fail**, все падения `spawn EFTYPE` в `cli.e2e.test.ts` и `executor.test.ts` |
| Запуск без ключа | `untildone run --plan plan.md` | `no Deep Infra API key` — жёсткий отказ до любой работы |
| Запуск с фиктивным ключом | `DEEPINFRA_API_KEY=dummy` | `opencode CLI not found` — **при установленном opencode v2.2.0 в PATH** |
| Spawn исполнителя | `spawn('opencode', ['--version'], {detached:true})` | **ENOENT** |
| Spawn через `.cmd` | `spawn('opencode.cmd', ...)` | **EINVAL** (Node требует `shell:true` для `.cmd`) |
| `--check` | `Get-Command sh` | `sh` отсутствует; `runCheck` вызывает `spawnSync('sh', ['-c', cmd])` |

Итог: три независимых блокера на Windows — ключ, spawn исполнителя, `sh` для проверок.
Любой из них достаточен, чтобы цикл не запустился.

## Почему это не «надо просто настроить»

- `opencode` в PATH представлен `opencode.ps1` / `opencode.cmd`. Node без `shell:true`
  такие файлы не запускает, а `shell:true` несовместим с `detached:true`, который
  используется для kill process group.
- Проверка `opencode --version` идёт через `spawnSync` и падает до цикла.
- `runCheck` жёстко зашивает POSIX `sh`; на Windows без Git Bash любая `--check`
  команда возвращает код 1, то есть выглядит как проваленный тест.
- `killCurrentStep` использует `process.kill(-pid)`, то есть группы процессов POSIX.

Это архитектурная POSIX-ориентация, а не отсутствующая настройка.

## Сравнение с локальным плагином

| Свойство | `untildone` | `task-continuity` (наш) |
|---|---|---|
| Где работает | внешний процесс, дочерние `opencode run` | внутри интерактивной сессии |
| Windows | **не работает (проверено)** | работает на этой машине |
| Внешние ключи | обязателен Deep Infra | не нужны |
| npm-пакет | нет (404) | локальный, не публикуется |
| Сигналы прогресса | tool-события, git, worktree, чекбоксы | digest checklist |
| Оценка завершения | отдельная модель-судья + `--check` | чекбоксы и отчёт агента |
| Реакция на стагнацию | `noProgress` → пересоздание сессии | 3 неизменных digest → отключение |
| Лимиты | 30 итераций / 120 минут по умолчанию, настраиваются | 12 продолжений, 3 повтора |
| Возобновление | `resume <run-id>` из сохранённого состояния | повторный `enable` вручную |
| Защита от дублей | новый процесс на запуск, дедуп не требуется | id события + persisted `lastEventID` |
| Наблюдаемость | `.untildone/` логи, JSONL, счётчики | `status`, история последних событий |
| Стоимость | каждое исполнение + вызов судьи | только исполнения агента |

## Что стоит заимствовать

1. **Счётчик tool-событий как признак стагнации.** Наш плагин видит только чекбоксы;
   агент может «работать» без единого инструмента. Это дешёвый и полезный сигнал.
2. **Внешний детерминированный гейт** (`--check 'npm test'`). Галочка не равна
   пройденному тесту; команда с кодом возврата — равна. Реализуемо без внешнего процесса.
3. **`resume` по сохранённому run-id** вместо ручного `enable`.
4. **Счётчик итераций без прогресса** — у нас есть, но привязан только к digest файла.

## Чего не делать

- Не ставить `untildone` на Windows «для пробы»: он не запустится.
- Не переносить его как зависимость: пакет не опубликован, установка только из git.
- Не заменять наш плагин внешним супервизором в интерактивном чате: это другой режим
  работы (отдельный процесс, дочерние сессии, свой state-каталог).
