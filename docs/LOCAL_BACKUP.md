# Резервное копирование локальных записей

## Desktop

Закройте приложение и убедитесь, что запись/финализация завершена. Копируйте каталог данных приложения целиком: SQLite вместе с аудиофайлами и служебными файлами восстановления. Копия одного SQLite не содержит звук; копия одной БД во время записи без согласованного backup может быть неполной. Модели можно хранить отдельно, но не удаляйте архивы/raw до проверки копии.

Проверка: восстановите копию в отдельном тестовом профиле, откройте историю, прослушайте записи и проверьте текст/папки. Не заменяйте рабочий профиль до проверки. При rollback используйте копию, сделанную до upgrade; не понижайте схему вручную и не удаляйте новые таблицы.

## Web

Аудио находится в OPFS, метаданные/тексты/папки — IndexedDB одного origin. Очистка site data, смена профиля, домена или порта не переносит эти данные автоматически. Экспортируйте аудио каждой нужной записи и текст через UI до очистки. Это переносимые файлы, но не полный restore папок и журнала.

Полный автоматический backup/restore OPFS+IndexedDB пока не реализован. Поэтому не обещается восстановление полной иерархии из скачанных аудиофайлов; импорт восстанавливает аудио как новые записи. Не используйте синхронизацию одного SQLite-файла как замену логическому облачному журналу.

## Миграция папок

Native добавляет recording_folders/recording_positions, не перемещая физический звук. Browser повышает IndexedDB до v2, добавляя organization metadata, не изменяя OPFS-пути. Старые записи без папки остаются в root. Проверки миграции сохраняют ID, аудиобайты и текст; SQLite save транзакционен, IDB upgrade транзакционен. При сообщении о блокировке upgrade закройте старые вкладки, не удаляйте site data.
