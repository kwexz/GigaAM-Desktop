# GigaAM Desktop: текущие возможности Web

Проверено 2026-10-28 на Windows, Microsoft Edge, localhost. Это описание проверенных границ рабочей версии, а не обещание готовности всей дорожной карты.

## Как проверить

```powershell
npm ci
npm run dev -- --host 127.0.0.1 --port 4173 --strictPort
```

Откройте `http://127.0.0.1:4173/`. Для размещения на VPS используйте HTTPS: доступ к устройствам и OPFS требует безопасного контекста. HTTP на чужом хосте не является поддерживаемым режимом. Приложение не должно зависеть от обязательного центрального VPS.

## Проверенные сценарии

- Запись синтетического микрофона через основной интерфейс, pause/resume и Stop.
- Запись при отключённой сети после загрузки страницы.
- Сохранение аудио в OPFS, метаданных в IndexedDB; reload, playback и скачивание.
- Явный fallback при отказе display capture, создание вложенных папок и перенос записи через select и drag-and-drop, сохранение после reload.
- Проверка SHA-256 небольшого архива. Архивы больше 16 МиБ не получают выдуманный hash: streaming integrity для них ещё не завершена.
- Восстановление interrupted-state без фиктивного completion, durable range/sequence replay из OPFS, отказ gap и идемпотентный duplicate append.
- Mock WebSocket reconnect до ACK и последующий durable ACK/drain; это тест протокола, не реальный VPS inference.
- Инъекция metadata quota failure сохраняет уже записанные OPFS-байты; Stop останавливает захват при отказе хранилища.

Автоматическая проверка: `$env:PLAYWRIGHT_CHANNEL='msedge'; npm run test:web -- --workers=1`. Основной сценарий — `tests/web/application.spec.ts`; два capture-harness теста — отдельные низкоуровневые проверки. Они используют синтетические источники, не физические устройства.

## Источники и форматы

Доступность системного аудио определяется фактической audio track после выбора экрана/вкладки. Отсутствие track не считается успешным захватом. В режиме «система + микрофон» доступен микрофонный fallback; в system-only требуется явно выбрать другой источник. Браузеры и ОС отличаются: Chrome, Firefox, Safari и macOS в этой матрице не проверены.

Браузер выбирает поддерживаемый MediaRecorder MIME: Ogg/Opus, иначе WebM/Opus, иначе WebM. Расширение соответствует контейнеру. Desktop FLAC/WAV/MP3 не означают, что браузер умеет записывать эти форматы. Веса ASR автоматически не скачиваются.

## Remote ASR и облако

URL remote ASR необязателен; допустим WSS либо WS на localhost. Токен вводится в памяти страницы и не сохраняется в localStorage. Локальный архив не зависит от сети. Проверка протокола и отображение настроек не доказывают работающий удалённый ONNX ASR: серверная конфигурация, декодирование и full inference остаются непроверенными.

Реальные Google Drive/Яндекс.Диск ещё не подключены к законченному пользовательскому сценарию. Низкоуровневые adapters, chunk transfer и outbox не равны готовой синхронизации. Client ID и согласие отложены пользователем. Desktop должен использовать поддерживаемую нативную авторизацию без обязательного публичного URL; self-hosted Web — OAuth-настройки владельца установки и зарегистрированный callback его домена.

## Ограничения хранения и восстановления

Данные привязаны к origin и профилю браузера. Очистка site data удаляет локальную историю и звук; смена домена или порта создаёт другой origin. Запрос persistent storage может быть отклонён. Перед очисткой профиля скачайте нужные записи. Полный backup/restore OPFS+IndexedDB и recovery/quota acceptance ещё не завершены; не считать локальную историю независимой резервной копией.

Открытие приложения с нуля без сети и service worker/offline shell не проверены. Offline capture здесь означает работу уже загруженной страницы, а не гарантированный offline cold start.
